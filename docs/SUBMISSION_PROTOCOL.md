# 人工提交操作手册

20 道题 × 3 个产品 = 60 次提交。每次提交都要你在产品界面上手工做一遍，另外有三个命令帮你做三件事：准备每道题的题面和素材、记录时间和追问次数、校验导出的文件。

每条命令里的产品代号都用同一个写法：全小写，词与词之间用短横线隔开。代号会写进目录名，中途要是改了写法，工具就当成另一个产品，先前准备好的目录你就用不上了。

`--attempt` 是这个产品的提交轮次，第一轮填 1，命令里不写就按 1 算。进第 2 轮时每条命令都加 `--attempt 2`，目录名里的 `_1` 也跟着变成 `_2`。

## 保密

`submissions/` 下面的全部内容都不要贴进群聊、发给同事、贴给 AI 助手，也不要传到任何联网的网站或工具上，`spec.json`、`prompt.txt`、素材文件、校验输出都算在内。

别人只要拿到一个素材文件名，就能反查出这是哪道题。这些素材文件名在公开的 GDPval 全集里不重复，一个文件名只对应一道题。贴出一个素材文件名，等于告诉外人我们选了哪道题。三个产品的厂商知道我们选了哪些题，就能专门针对这些题优化自己的产品。三个产品的第一轮全部做完之后，我们才会公布选了哪些题，这是事先定好的披露规则。这些文件名一贴出去就收不回来，也没有补救办法。

跟别人说到某一道题，就用「题07」这样的序号称呼它。

## 开工前的准备

```bash
uv run python scripts/prepare_inbox.py --product <产品代号>
```

这条命令跑完之后，`submissions/inbox/<产品代号>_1/` 下面会有 20 个 `tNN/` 目录，每个目录里装三样东西：

| 文件 | 内容 |
|---|---|
| `prompt.txt` | 题面原文，整段贴进产品 |
| `materials/` | 这道题的素材文件，全部上传给产品 |
| `spec.json` | 这道题要求的交付格式、素材件数、时间上限、追问次数上限 |

这条命令可以反复跑。已经准备好的题它会跳过，素材也不会再下载一遍；本机上的素材文件损坏或者少了，它比对 sha256 时会发现，重新下载一遍。

三处编号是同一个数：「题07」在命令里填 `--ordinal 7`，对应的目录是 `t07`。

开工前确认三件事：一是你能登进这个产品的账号；二是你知道这个产品导出的文件存到本机哪个目录；三是 `spec.json` 里的 `material_count` 和 `materials/` 里的实际件数一样。

## 每道题的流程

**1 · 开始计时**

```bash
uv run python scripts/log_submission.py --product <产品代号> --ordinal <题序号> start
```

命令会把开始时间写进 `submission.json`，你不用手动填。这条命令每道题只能跑一次：它新建 `submission.json`，文件已经在了就直接报错退出，既不读里面已有的记录，也不覆盖它。

**2 · 提交**

把 `prompt.txt` 整段贴进产品，把 `materials/` 里的文件全部上传。素材传不上去，或者产品只收下其中几件，按下面「异常处理」一节的做法把这道题记下来。不要为了让产品收下就改题面。

**3 · 限时 30 分钟**

30 分钟从 `start` 记下的那个时间点开始算。30 分钟到了，产品还没给出可以导出的文件，按 `product_error` 收尾；产品已经结束了这一轮、什么文件都没给，按 `no_output`。

**4 · 只能追问一次**

产品给出的答复不完整时，可以追问一次，用一句固定的话。你怎么问会影响这道题的分数，所以三个产品都用同一句，一个字都不要改。开工前把这句话定下来，抄在手边。

每追问一次，跑一次这条命令：

```bash
uv run python scripts/log_submission.py --product <产品代号> --ordinal <题序号> followup
```

追问超过一次，命令照样把这一次记下来，另外在终端打印一条警告。它不会阻止你多问一句，但每一次追问都会留下记录，这些次数会如实写进报告。你当场记下来，比事后回忆准确。

**5 · 导出主交付物**

产品输出了好几个文件，就挑一份当主交付物，放进：

```
submissions/outbox/<产品代号>_1/tNN/
```

这个目录在你跑 `start` 的时候就建好了，不用自己新建——自己建容易把路径拼错，文件放进去校验的时候找不到。

其余文件放进同一个目录下的 `attachments/`，判分的时候不看它们。GDPval 给的标准答案每题只有一份文件、只有一种格式，判分器也是每题只取一份。

`.DS_Store`、`~$` 开头的 Word 锁文件、还没下载完的 `.crdownload`，都不用手动清理，校验的时候工具会自动跳过它们。

**6 · 收尾登记**

```bash
uv run python scripts/log_submission.py --product <产品代号> --ordinal <题序号> finish \
  --outcome delivered \
  --note "" \
  --product-build "<产品版本号>" \
  --deliverable-filename "<主交付物文件名>"
```

`--product-build` 填产品界面上能看到的版本号或者日期。产品要是在测评期间更新了版本，这件事要写进报告。

## 异常处理

`--outcome` 有五个取值，按实际发生的情况选，**不要为了凑出一份文件反复重试**。工具不会限制你重试几次，但试的次数一多，三个产品就没法放在一起比了。按实际情况记一个 outcome，这道题就到此结束：它按 0 分算进总分，报告里也会把它标出来。产品这一题确实做不出来，0 分就是这道题的真实结果。

| 情况 | `--outcome` |
|---|---|
| 导出了可以判分的文件 | `delivered` |
| 产品没有给出任何文件 | `no_output` |
| 产品只给出在线预览或者分享链接，导不出文件 | `link_only` |
| 导出的格式不在 xlsx / docx / pptx / pdf 这四种之内 | `unsupported_export` |
| 产品报错、崩溃、卡死，或者超过 30 分钟没有出结果 | `product_error` |

后面这四种情况都不用填 `--deliverable-filename`。`--note` 里把现场情况写清楚，你写的这段话会进报告，用来说明这道题的情况。

**产品给错格式**（题目要 xlsx，它给了 pdf）：只要格式在四种之内，就照 `delivered` 记录，把文件交上去。校验命令会标一条 `format_mismatch` 警告，但不会拦停；判分器检查格式的时候会照实扣分。不要自己动手转格式。你要是手工补上产品没做到的事，判分器会把你补的这一步也当成产品的成果打分。

**素材传不上去**：有些题的素材件数多，可能超过产品一次能接收的附件数量上限。记 `product_error`，在 `--note` 里写明传上去了几件、卡在第几件。这些记录攒到一块，就能拼出一张对照表：每道题有几件素材，每个产品一次最多收几件。

**要换交付物**：你已经 `finish` 过，又想换一份文件，不要直接覆盖，把 `--attempt` 加 1，这道题重新跑一遍。判定结果按 `(产品, 轮次)` 分开存档。你要是在同一轮里换掉文件，这道题的分数里既有旧文件得的分，也有新文件得的分，事后谁也分不出哪一分是哪份文件得的。

## 收尾校验

20 道题全部做完之后跑：

```bash
uv run python scripts/check_outbox.py --product <产品代号>
```

它会把每道题的状态逐条打印出来，退出码分三种：0 表示可以进入判分，1 表示有拦停的问题，2 表示前置条件不满足，比如 inbox 还没准备好。

`flags` 里的问题分两类。下面这些会拦停，你必须处理完才能进入判分：

| flag | 含义 |
|---|---|
| `missing` | 目录里找不到交付物 |
| `multiple` | 目录里有多份候选文件，工具认不出哪一份是主交付物 |
| `unparseable` | 文件打不开，或者格式不在四种之内 |
| `empty` | 文件里提取出的文字不到 200 个字符 |
| `material_echo` | 你交的文件和某一件素材逐字节相同，就是素材原件 |
| `log_missing` / `log_incomplete` / `log_unparseable` | `submission.json` 找不到、字段不全，或者不是合法的 JSON |

碰到 `empty` 和 `material_echo`，不要靠反复重试绕过。产品确实只给出一个空文件，就记 `no_output`；产品确实把素材原样退了回来，那就是产品这一题没做出来，按上面「异常处理」一节记一个 outcome，这道题到此结束。

下面这一条只是提醒，不拦停：

| flag | 含义 |
|---|---|
| `format_mismatch` | 导出格式和题目要求的格式不一致，文件照原样交上去就行 |

命令最后会把三个产品的全部交付物放在一起比对，同一份文件出现在两个位置，它就拦停。同一份文件要是放进了两道题的目录，或者复制到了另一个产品的目录，报告里比出来的结果就是假的。

三个产品全部做完之后，判分器按题序号取文件，取到的文件要和校验时记下的那一份逐字节一致。校验通过之后你要是再换文件，判分器会报错，这道题进不了判分。
